# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

MCP-сервер для чтения и правки конфигураций `.fscp` — файлов СПЗ «Рубеж-Глобал»
(Windows Global Monitor). Версия 2 — чтение и запись; исходный файл не
перезаписывается никогда, только «сохранить как».

Отвечать пользователю на русском.

## Команды

Интерпретатор в `PATH` — это заглушка из `WindowsApps`, она не работает.
Всегда вызывать Python явным путём. Пакет заявлен как 3.11+ (на машине стоит
3.14, остальные версии проверяет матрица в `.github/workflows/tests.yml`).

```bash
py -3 -m venv .venv
```

```bash
.venv/Scripts/python.exe -m pip install -e ".[dev,img]"
```

```bash
.venv/Scripts/python.exe -m pytest -q
```

Один тест или файл:

```bash
.venv/Scripts/python.exe -m pytest tests/test_devices.py -k адрес -q
```

Запуск сервера вручную (обычно не нужен — его поднимает Claude Code по `.mcp.json`):

```bash
.venv/Scripts/python.exe -m fscp_mcp
```

Кириллица в консоли Windows превращается в mojibake — при ручных прогонах
ставить `PYTHONUTF8=1 PYTHONIOENCODING=utf-8`. В самом сервере кодировка
выставляется в `__main__.py`, в `.mcp.json` продублирована через `env`.

## Формат .fscp

ZIP (deflate) с фиксированным набором записей. XML — выхлоп .NET `XmlSerializer`
(`xmlns:xsd`/`xmlns:xsi`, `xsi:nil="true"`, UTF-8 без объявления encoding,
отступ 2 пробела). У каждого корня свой `<Version>`.

| Запись | В охвате | Содержимое |
|---|---|---|
| `GKDeviceConfiguration.xml` | чтение + запись | дерево устройств `RootDevice`, зоны, задержки, направления, МПТ, шаблоны параметров |
| `PlansConfiguration.xml` | чтение + запись | графические планы и объекты на них |
| `Content/<guid>` | чтение + запись | подложки планов, **без расширения** |
| `SystemConfiguration.xml` | только перечисление | звуки, автоматика, организации |
| `LayoutsConfiguration.xml` | только перечисление | раскладки АРМ |
| `SecurityConfiguration.xml` | **никогда** — ни читать, ни писать осмысленно | пользователи и SHA-512 хеши паролей; переносится байтами как есть |
| `Resources/` | — | директория-запись, иногда с файлами (например `.mp3`) |

### Сериализация (запись)

Побайтовая точность — не цель, а требование: файл, разобранный и записанный
без единой правки, обязан совпасть с исходным до байта на всех 40 XML-записях
восьми доступных рабочих конфигураций (`writer.py`, `tests/test_real_configs.py`).
Тогда любое расхождение в сохранённом файле — это правка, а не артефакт
сериализатора.

* декларация ровно `<?xml version="1.0"?>` — без `encoding`, без `standalone`;
* перевод строки **берётся из байтов конкретной записи**, а не выбирается: почти
  везде CRLF, но встречается и LF в пределах одного архива (`writer.root_header`);
* объявления `xmlns` на корне сохраняются **дословной строкой из исходника** —
  у `GKDeviceConfiguration` это `xmlns:xsd` + `xmlns:xsi`, у `PlansConfiguration`
  бывает только `xmlns:xsi`; `ElementTree` теряет неиспользуемый префикс;
* отступ 2 пробела, пустой элемент — `<Foo />` с пробелом перед слешем;
* смешанного содержимого (текст + дети в одном элементе) в формате не бывает —
  проверено на 2 363 942 элементах; `writer.serialize` на таком поднимает
  `FscpError`, а не молча теряет текст.

### ZIP при сохранении

Порядок записей **нестабилен между версиями программы** (в одной из
25-МБ конфигураций нет отдельной записи `Content/`, а `Resources/` стоит в
середине списка). `fscp_save` копирует порядок исходника как есть; для нового
файла (`fscp_create`) порядок задаёт `skeleton.LAYOUT`. Блобы `Content/*`
несут **собственные исходные таймстампы**, отличные от таймстампа сохранения
конфигов, — при сохранении их метаданные копируются как есть, только у
изменённых записей `date_time` становится текущим. `zipfile.ZipFile.writestr`
мутирует переданный `ZipInfo` (включая `external_attr`) — `save()`
восстанавливает его значение сразу после записи, до того как `close()`
запишет центральный каталог.

### Адресация устройств

У устройства **нет поля `Name`** — только `UID`, `DriverUID` и `IntAddress`.
Отображаемое имя и адрес вычисляются. Правило выведено сверкой с полем `Name`
объектов на планах, где то же имя уже посчитано самим Global Monitor
(~20 тыс. проверочных случаев в рабочих конфигурациях), и живёт в
`FscpArchive._address_for` — **менять только вместе с прогоном
`tests/test_real_configs.py` при заданной `FSCP_TEST_CONFIGS`**: синтетика в
`tests/test_devices.py` ловит только сами правила, а не расхождение с
Global Monitor.

1. дети «Локальной сети» (`РСГК` или `ГК`) нумеруются по порядку — это первый
   компонент адреса;
2. объект с флагом `no_address` (`ГК`, «Группа реле», «Линия БМП») своего адреса
   не имеет и показывает адрес родителя;
3. дети **сквозного узла** — группового устройства (`is_group`: МВК4, РМ2, АМ4)
   или того же `no_address`-контейнера — стоят на одном уровне с ним, а не
   уровнем ниже: их абсолютный `IntAddress` заменяет последний компонент адреса
   родителя;
4. иначе `IntAddress` дописывается к адресу родителя.

`ГК` показывается по своему IP (`GKProperty` `IPAddress`/`StringValue`), а не по
номеру. К имени устройства, у которого заполнено `Description`, добавляется
`(описание)` без пробела.

Совпадение с подписями на планах — **~96,7 %**. Остаток объясним и не является
ошибкой: подписи кэшируются при отрисовке и устаревают после перенумерации АЛС
(инструмент `validate_config` их и ловит), плюс внутренние индикаторы ГК имеют
своё оформление имени.

### Связи по GUID

Всё ссылается на всё голыми GUID'ами: `ZoneUIDs`/`GuardZoneUIDs` → зоны,
`PlanElementUIDs` → объекты планов, `GKClause` → устройства/зоны/сценарии/
направления/МПТ/НС. Объект плана ссылается на объект ГК парой
`ItemUID` + `ObjectName` (`GKDevice` | `GKZone` | `GKDelay` — объект сценария).

**Связь план↔объект двусторонняя.** `ItemUID` объекта плана смотрит на объект
ГК, а `PlanElementUIDs` этого объекта ГК держит обратную ссылку — UID самого
объекта плана. Правя одну сторону (`place_object`/`remove_placement` в
`edits.py`), обязательно править и вторую: односторонняя связь — это и есть
висячий GUID, который никто не объяснит. `validate.one_sided_links` это ловит.

Разрешать GUID через `logic.resolve()` либо инструментом `resolve_uid` —
руками по индексам не искать.

**Обратный индекс ссылок** — `FscpArchive.refs_to: dict[uid, list[Reference]]`,
строится в `_index_refs()` (`archive.py`) тем же проходом, что и остальные
индексы. `archive.referrers(uid)` отвечает на вопрос «кто на это ссылается» —
без него удаление объекта оставляло бы висячие GUID'ы. Все мутации,
удаляющие объект (`remove_device`, `remove_object`, `remove_plan`), либо
отказывают при непустых ссылках, либо, при `force=true`, каскадно их
вычищают через `edits.drop_references()`.

### Подложки планов

Поля `BackgroundImageSource` / `BackgroundSVGImageSource` / `ImageSource` несут
значения **двух разных видов**, и их нельзя путать:

* GUID → запись `Content/<guid>` в этом же архиве;
* путь ресурса приложения (`GKModule/Images/Zone.png`, `PlansModule/Images/CMap.png`)
  → иконка, зашитая в Global Monitor, в архиве её нет.

Различает их `views.image_reference()`. Блобы лежат без расширения — тип только
по сигнатуре: в рабочих конфигурациях попадаются и PNG, и JPEG — не считать всё
PNG. Размеры читаются из
заголовка (`IHDR` / `SOF`) без декодирования, потому что оригиналы бывают
5000×4749.

## Архитектура

Слои снизу вверх, зависимости строго в одну сторону:

| Модуль | Роль |
|---|---|
| `errors.py` | `FscpError` — единственный тип ошибки, реэкспортирован из `archive.py` |
| `drivers.py` + `drivers.json` | справочник 102 драйверов Рубеж по GUID |
| `images.py` | сигнатуры и размеры блобов `Content/` |
| `writer.py` | сериализатор ElementTree → байты в формате `XmlSerializer`. Про ZIP не знает |
| `archive.py` | `FscpArchive`: ZIP-чтение и -запись, разбор XML, **все индексы**, сессионный кэш, журнал правок |
| `logic.py` | рендер `GKClause` в русский текст |
| `schema.py` | канонический порядок полей и заготовки новых элементов |
| `edits.py` | мутации дерева на месте + запись в журнал |
| `validate.py` | проверки целостности: ошибки блокируют `fscp_save`, предупреждения — нет |
| `skeleton.py` + `skeleton/*.xml` | шаблон для `fscp_create` |
| `views.py` | сборка словарей-ответов из узлов XML, включая рендер журнала |
| `paging.py` | страничная выдача |
| `server.py` | 37 инструментов MCP (20 на чтение, 17 на запись) |

`archive.py` читает и пишет ZIP; ничего другого про контейнер не знает ни один
модуль. `archive.py` — единственное место, где строятся индексы. Новый вид
запроса — это новый индекс там же, а не обход коллекций в `views.py`:
конфигурация в 5656 устройств не переживает линейного скана на каждый вызов.
Уже есть `devices_by_uid`, `devices_by_address`, `devices_by_zone`,
`objects_by_uid`, `objects_by_kind`, `plans_by_uid`, `plan_children`,
`plan_objects_by_item`, `plan_objects_by_plan`, `images`, `image_refs`,
`refs_to` (обратные ссылки по GUID).

**Сессии.** `fscp_open` разбирает архив один раз (25 МБ XML ≈ 0,7 с) и отдаёт
`handle`; дальше всё работает по нему. Кэш — не больше `MAX_SESSIONS = 3`
архивов. Вытеснение и инвалидация по `mtime` **пропускают сессии с
несохранёнными правками** (`archive.dirty`) — иначе часть работы исчезла бы
молча при открытии четвёртого файла или при изменении исходника на диске.
Открывать архив внутри других инструментов нельзя.

**Ошибки.** Всё ожидаемое — `FscpError` с текстом для пользователя. Декоратор
`server.tool` в `server.py` превращает его в `{"error": ...}`, поэтому в ответ
инструмента трейсбек не попадает. Не заменять на голые `raise`.

**Запись.** Мутации в `edits.py` правят живое дерево **на месте** — вставляют,
удаляют, переписывают текст, но никогда не пересобирают дерево целиком: на
идентичности узлов держится исключение вложенных планов в `_index_plans`, а
снимок для `fscp_revert` — это сырые байты записи, а не копия дерева.

Каждая мутация: проверяет предусловия → правит дерево → `archive.dirty.add(entry)`
→ `archive._reindex()` → `edits.record(...)` в журнал. Переиндексация полная,
не инкрементальная — 0,16 с на самой большой конфигурации (5192 устройства),
дешевле и надёжнее частичной инвалидации. Следствие: `Device`/`ObjectRef`
после переиндексации пересоздаются — не держать ссылку на них через мутацию,
перезапрашивать по UID.

`fscp_save(handle, out_path, overwrite=False, check=True)` собирает новый ZIP:
изменённые записи — через `writer.serialize`, остальные — побайтово из
исходника, метаданные (`date_time`, `compress_type`, `external_attr`) и порядок
записей сохраняются. `out_path` не может совпадать с исходным путём — это
жёсткое ограничение, не настройка. `check=True` по умолчанию гоняет
`validate.preflight` и отказывает при найденных нарушениях.

`fscp_revert` возвращает дерево к состоянию на момент открытия, разбирая
заново сжатый снимок исходных байтов (`FscpArchive.baseline`), а не полагаясь
на файл — тот мог с тех пор измениться. Частичного отката (до конкретного
шага) нет: перечитать дешевле, чем городить обратные операции на каждую
мутацию.

## Правила, которые легко нарушить

- **Ничего не отдавать целиком.** Любая коллекция — через `paging.page()`.
  Дерево — через `views.tree_text()` с потолком `MAX_TREE_NODES`.
- **Подложки не возвращать инлайном** без явного `max_px`: оригинал 5000×4749
  разорвёт контекст. Основной путь — `extract_plan_image` на диск и обычное
  чтение файла.
- **`SecurityConfiguration.xml` не читать** ни через `read_xml`, ни иначе — в
  том числе при сохранении. Она переносится в новый архив непрозрачными
  байтами (`archive.py: entry_bytes`), ни разу не будучи разобранной. «Не
  читать» значит «не разбирать и не показывать», а не «потерять».
- `ParameterTemplates` содержит вложенные `GKDevice` — это **шаблоны**, а не
  устройства. `grep -c '<GKDevice>'` даёт завышенный счёт; дерево строится
  только обходом `RootDevice/Children`.
- **Новый элемент — только через `schema.insert_ordered`**, никогда через
  `append`. `XmlSerializer` на неожиданном порядке полей не падает — он
  **молча пропускает поле**. Файл откроется, настройка потеряется, никто не
  заметит. Канонический порядок в `schema.py` снят с рабочих конфигураций
  (для `GKDevice` — 25 385 устройств, 0 нарушений), а не выведен из общих
  соображений.
- **После мутации — `archive._reindex()` и заново запросить объект по UID.**
  `Device`/`ObjectRef`, полученные до правки, после переиндексации ссылаются
  на устаревшее состояние.
- **`IntAddress` не уникален среди братьев** — уникальна пара
  `(DriverUID, IntAddress)`. У БМП рядом законно стоят «Линия БМП», БМПК и
  БМПП с одним адресом (42 таких случая на 8 конфигурациях). Проверка —
  `edits.taken_addresses`, `validate.address_conflicts`.
- **Адрес ищется по всей линии, а не только среди братьев.** Дети сквозного
  узла (МВК4, РМ2, АМ4) стоят на одном уровне с ним и тоже занимают адреса —
  `edits.line_addresses` считает по префиксу вычисленного адреса, а не по
  `Children` напрямую.
- **`No` объектов коллекций не перенумеровывать.** Это стабильный
  идентификатор с дырами (в рабочих конфигурациях — до 1025 при 263 зонах), а
  не позиция. Имя объекта показывается как `"{No}.{Name}"`, и перенумерация
  переименовала бы всех соседей и устарила бы их подписи на планах.
- **Правка адреса/описания устройства обязана обновить его подписи на
  планах** — `edits.refresh_plan_labels`. Поле `Name` объекта плана — это
  сохранённый при отрисовке кэш, а не ссылка; не обновив его, инструмент сам
  произведёт ту самую «устаревшую подпись», которую `validate_config` ловит
  как дефект.
- **Удаление объекта — только через каскад** (`edits.drop_references`,
  `prune_empty_clauses`), не голым `element.remove`. Иначе останутся висячие
  GUID'ы в `ZoneUIDs`, в условиях логики или (что хуже) условие логики без
  единой цели — то, чего не бывает ни в одной рабочей конфигурации.
- **Создавать можно только объекты, чей вид описан в `schema.OBJECT_KINDS`**
  (сейчас — зоны и сценарии). Направления, МПТ, охранные зоны, двери, зоны
  СКД пусты во всех доступных конфигурациях; угаданная схема сломает файл
  молча. Редактирование и удаление уже существующих объектов такого вида
  работает без схемы.
- **`copy.deepcopy(self.gk)` не делать никогда** — 25 МБ XML разбирается в
  ~150 МБ дерева, и снимок такого объёма на каждую мутацию или каждый откат
  недопустим. Снимок для `fscp_revert` — сжатые исходные байты
  (`FscpArchive.baseline`), не копия дерева.
- `fscp_save` пишет только в новый путь; `out_path`, совпадающий с исходным
  файлом сессии, — это `FscpError`, а не разрешённый со предупреждением кейс.

## Тесты

Реальные конфигурации в репозиторий не выкладываются: в них данные объекта и
`SecurityConfiguration.xml`. Поэтому тесты двухуровневые.

**Базовые** идут в любом клоне на синтетическом архиве из `tests/factories.py`:
он собирает ZIP с тем же набором записей и тем же выхлопом `XmlSerializer`
(CRLF по умолчанию, канонический порядок полей — через `writer.serialize`,
а не руками в f-строках), а дерево устройств в нём подобрано так, чтобы задеть
все четыре правила адресации. Ожидаемые значения — константы того же модуля
(`EXPECTED_DEVICES`, `IP_NAME`, `GROUP_CHILD_ADDRESS`, `LINE_ADDRESS`, …);
правя генератор, правь и их.

| Файл | Что проверяет |
|---|---|
| `test_archive.py`, `test_devices.py`, `test_plans_images.py` | чтение: индексы, адресация, подложки |
| `test_writer.py` | сериализатор побайтово, пересборка ZIP, метаданные, отказы `save()` |
| `test_edits.py` | мутации устройств: адреса, перенос, удаление с каскадом, откат |
| `test_objects_plans.py` | зоны/сценарии, логика `GKClause`, планы, двусторонняя связь план↔объект |
| `test_create.py` | `fscp_create`: обезличенность шаблона, донор `SecurityConfiguration.xml` |
| `test_tools.py` | весь MCP-слой через `server.call_tool` |
| `test_real_configs.py` | round-trip сериализатора, инварианты адресации, скорость, устаревшие подписи |

**По реальным конфигурациям** — `tests/test_real_configs.py`, каталог задаётся
переменной `FSCP_TEST_CONFIGS`; без неё файл пропускается целиком. Там же живёт
побайтовая проверка сериализатора: каждая XML-запись каждой конфигурации
разбирается и пишется обратно, результат обязан совпасть с исходником до
байта — это единственная проверка, что `writer.py` действительно воспроизводит
формат самого Global Monitor, а не просто симметричен сам себе. Прогонять при
любой правке `_address_for`, `writer.py` или `schema.py`:

```bash
FSCP_TEST_CONFIGS=<каталог с .fscp> .venv/Scripts/python.exe -m pytest -q
```

Тесты MCP-инструментов идут через `server.call_tool`, а не вызовом функций
напрямую, — иначе не проверяется схема и обработка ошибок. У вспомогательного
`call()` в `test_tools.py` первый параметр называется `tool`, а не `name`:
несколько инструментов записи (`add_object`, `add_plan`, …) сами принимают
аргумент `name`, и совпадение имён ловилось бы `TypeError` при каждом вызове.

**Фикстура `handle` из `conftest.py` кэширует один и тот же `FscpArchive` на
всю тестовую сессию** — `open_archive` дедуплицирует по `(path, mtime)`, а
файл `synthetic_path` не меняется между тестами. Для тестов **чтения** это
не проблема, но тест **записи**, использующий эту фикстуру и не откативший
свою правку, протечёт в следующий тест. Правило: тесты записи открывают
собственный файл через свою фикстуру (см. `opened` в `test_edits.py` или
`write_handle` в `test_tools.py`), а не разделяют `handle`.
